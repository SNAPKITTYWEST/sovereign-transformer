## WHAT IS SOVEREIGN-TRANSFORMER?

A **3-endpoint autonomous agent orchestrator** that operates 31 specialized agents through:

1. **Terminal Interface** (Git Command Center) — retro DOS aesthetic + command palette
2. **Web Frontend** (Twin-O-Matic / foundry-intel) — visualization + interaction
3. **Desktop App** (ABZU IDE) — Elixir + J Language + Phoenix LiveView

Every command is **routed through 31 specialized agents**, **verified by Lean 4 mathematics**, and **sealed immutably to WORM** (Write Once Read Many blockchain).

## THE CANONICAL COMMAND

```
] ASK "audit this code for security"
```

What happens next:

1. **Router SACM Gate** patterns the input → "audit" = security analysis
2. **Ahmad-Relay** routes to SENTINEL agent
3. **SACM Mesh** orchestrates execution through marinating cycles + SLC gates
4. **Bedrock** invokes optimal LLM (DeepSeek R1 for reasoning, Mistral Codestral for code, etc.)
5. **S-AUTOCODE** compiles to SUBLEQ deterministic machine
6. **Lean 4** verifies proof mathematically
7. **WORM** seals operation immutably with Ed25519 signature
8. **Terminal displays** result + WORM seal hash

**Result**:
```
] ASK audit this code for security

> EXECUTION: ✅ S-AUTOCODE compiled
```

- Self-organizing agent network
- Membership verification
- Clearance-based access
- Marinating cycles (higher clearance = longer scrutiny)
- Two-pass SLC verification (before & after marinate)

### Marinate Cycle
```
Clearance 5: 2500ms (CIPHER, SENTINEL, MNEMEX, PHANTOM)
Clearance 4: 1500ms (ORACLE, NEXUS, FORGE, NOVA)
Clearance 3: 750ms (AXIOM, HERALD, FLUX)
Clearance 2: 250ms
Clearance 1: 0ms
```

### WORM (Write Once Read Many)
- Immutable append-only ledger
- Ed25519 signatures
- Merkle proofs
- BLAKE3 sealing
- Every operation sealed + hashed

### S-AUTOCODE
- SUBLEQ machine (1-instruction ISA)
- Deterministic execution
- Compile arbitrary code to SUBLEQ
- Generate witness/proof
- Lean 4 verifies
